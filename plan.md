# План разработки проекта «Активные перерывы» (Добрые Сайты 2026)

## 🎯 Цели и ограничения (на основе Правил конкурса, п. 1-4)
- **Сроки Этапа 1:** 16–22 ноября 2026 г. (осталось 4 дня).
- **Максимальный балл за Этап 1:** 70 + 3 бонусных за хостинг (п. 4.5).
- **Критические риски:**
  - Потеря до 10 баллов за отсутствие клавиатурной навигации и WCAG (п. 4.3).
  - Потеря до 10 баллов за «Работу с данными» (п. 4.2) — компенсируем через JSON + экспорт.
- **Стек:** React (Vite) + JSON-файлы + localStorage.
- **Хостинг:** GitHub Pages (бесплатно, упомянут в п. 3.2, 100% работает в РФ).
- **БД:** Не используется. Данные хранятся в JSON-файлах репозитория и localStorage браузера.

## 📅 Спринт разработки (18–22 ноября)

### День 1 (18 ноября): Структура проекта, JSON-справочники и онбординг
- [ ] **Инициализация проекта:** `npm create vite@latest Dobro_Active_Breaks -- --template react`.
- [ ] **Настройка роутинга:** `react-router-dom` с **HashRouter** (критично для GitHub Pages).
- [ ] **Создание JSON-справочников** в папке `public/data/`:
  - `health-issues.json` — 5–7 проблем (шея, глаза, спина, запястья, осанка, стресс, общее утомление).
  - `exercises.json` — 20–30 упражнений с полями: `id`, `title`, `description`, `duration_sec`, `issue_id`, `urgency_level`, `video_url` (опционально).
  - `tips.json` — советы по здоровью для экрана статистики.
- [ ] **Экран онбординга:** форма выбора «болевых точек» (чекбоксы с иконками) → сохранение в `localStorage` под ключом `healthProfile`.
- [ ] **Базовая семантическая разметка:** `<header>`, `<main>`, `<nav>`, `<section>`, `<footer>`.

### День 2 (19 ноября): Ядро сессии и прогрессивная система (State Machine)
- [ ] **Таймер сессии:** базовое время работы 52 мин, отдых 5 мин.
- [ ] **State Machine «Долг здоровья»:**
  - **Уровень 0 (Норма):** старт сессии / кнопка «Отметился» → базовый таймер, 1–2 лёгких упражнения.
  - **Уровень 1 (Долг):** 5 мин игнора ИЛИ кнопка «Не могу» → таймер работы ×0.6 (~31 мин), 3 упражнения, 10 мин отдыха.
  - **Уровень 2 (Критический):** повторный игнор → таймер ×0.3 (~15 мин), 4–5 упражнений, 15 мин отдыха.
  - Максимальный уровень — 2.
- [ ] **Динамическая выборка упражнений:** `fetch('/data/exercises.json')` → фильтрация по `issue_id` (из профиля) и `urgency_level` (из State Machine).
- [ ] **Сохранение сессии в localStorage:** ключ `sessions` — массив объектов `{id, date, duration, breaksDone, breaksMissed, healthScore}`.

### День 3 (20 ноября): Уведомления вне окна и Health ROI
- [ ] **Web Notifications API:** запрос прав при старте сессии, системные пуши.
- [ ] **Web Audio API:** звуковой сигнал в фоне (не `<audio>`, он блокируется в неактивных вкладках).
- [ ] **Page Visibility API + document.title:** мигание «⏰ Пора отдохнуть! | Активные перерывы» когда вкладка неактивна.
- [ ] **Vibration API:** вибрация на мобильных для уровня 2.
- [ ] **Расчёт Health ROI:** формула `clamp((breaksDone × 15) − (breaksMissed × 25), 0, 100)`.
- [ ] **Экран статистики:** прогресс-бар Health ROI, список сессий, текст «Вы сохранили X% дневного ресурса».

### День 4 (21 ноября): Экспорт данных, UX/UI и WCAG (КРИТИЧНО)
- [ ] **Экспорт/импорт данных (компенсация баллов за «Работу с данными»):**
  - Кнопка «Скачать мою статистику» → экспорт `sessions` + `healthProfile` в JSON/CSV.
  - Кнопка «Импорт» → загрузка ранее сохранённого файла.
  - Это покажет жюри умение работать с данными без серверной БД.
- [ ] **Клавиатурная навигация (10 баллов по п. 4.3):**
  - Полная навигация через `Tab` / `Shift+Tab`.
  - Видимый `:focus-visible` на всех интерактивных элементах.
  - Управление фокусом в модалках (ловушка фокуса, закрытие по `Esc`).
  - ARIA-атрибуты: `aria-label`, `aria-live="polite"` для таймера и уведомлений.
- [ ] **Адаптивность:** mobile-first, проверка на смартфонах/планшетах/десктопе.
- [ ] **Контрастность:** проверка цветов через WCAG AA (4.5:1).

### День 5 (22 ноября): Деплой на GitHub Pages и документация
- [ ] **Настройка Vite для GitHub Pages:**
  - В `vite.config.js`: `base: '/Dobro_Active_Breaks/'` (имя репозитория).
- [ ] **Деплой через `gh-pages`:**
  - `npm install -D gh-pages`
  - Скрипты в `package.json`: `predeploy: npm run build`, `deploy: gh-pages -d dist`.
  - `npm run deploy`.
- [ ] **Включение Pages в настройках репозитория:** Settings → Pages → Source: `gh-pages branch`.
- [ ] **Финализация README.md:** рабочая ссылка, инструкция по тестированию, описание работы с данными (JSON + localStorage + экспорт).
- [ ] **Финальное тестирование:** сценарий «ушёл в другую вкладку на 10 минут» → проверка пуша + звука + мигания title.
